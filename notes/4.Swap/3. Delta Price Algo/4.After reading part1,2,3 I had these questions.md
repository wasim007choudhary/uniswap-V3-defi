# Which Price Is Used In The Formula?

A very important question is

> **When we use the formula, which price do we substitute into `Pbefore`?**

The answer is

```text
The current market price before the swap.
```

**NOT**

```text
Pa (Lower Price Limit)
```

and

**NOT**

```text
Pb (Upper Price Limit)
```

Remember

```text
Pa = Lower Liquidity Boundary

Pb = Upper Liquidity Boundary

Pbefore = Current Market Price Before The Swap

Pafter = Current Market Price After The Swap
```

---

## Example

Suppose the active liquidity range is

```text
Pa = 1000

Pb = 2000
```

Current market price

```text
Pbefore = 1500
```

Current situation

```text
1000 ----------------------- 1500 ----------------------- 2000
 Pa                    Current Price                     Pb
```

A trader swaps Token0 into the pool.

When the formula is executed,

it uses

```text
Pbefore = 1500
```

It does **not** use

```text
1000
```

or

```text
2000
```

because those are simply the liquidity boundaries.

The current market price is what actually moves during a swap.

---

## After Applying The Formula

Suppose the formula calculates

```text
Pafter = 1420
```

Now the situation becomes

```text
1000 ----------------------- 1420 ----------------------- 2000
 Pa                    Current Price                     Pb
```

Notice

Both prices

```text
Pbefore

and

Pafter
```

are still inside the same liquidity range.

Only the current market price changed.

The liquidity boundaries remained exactly the same.

---

# What If The Formula Calculates A Price Outside The Current Range?

Now suppose the active range is

```text
Pa = 1000

Pb = 2000
```

Current market price

```text
Pbefore = 1500
```

A trader now swaps a very large amount of Token0.

---

## Step 1 — Apply The Formula

The formula receives

```text
Pbefore

Liquidity (L)

ΔX
```

and calculates

```text
Pafter
```

Suppose the result is

```text
Pafter = 900
```

Notice something interesting.

The formula simply performs the mathematical calculation.

It does **not** know whether

```text
900
```

is inside or outside the current liquidity range.

Its only responsibility is to answer

> "If this liquidity stayed active for the entire swap, where would the price end up?"

---

## Step 2 — Check The Liquidity Boundary

Current range

```text
1000 ----------------------- 1500 ----------------------- 2000
 Pa                    Current Price                     Pb
```

Formula says

```text
Pafter = 900
```

Immediately Uniswap checks

```text
Is 900 inside this liquidity range?
```

Answer

```text
No.
```

because

```text
900 < 1000
```

---

## Step 3 — Stop At The Boundary

Since the current liquidity only exists between

```text
1000

and

2000
```

the current price cannot move below

```text
1000
```

while using this liquidity.

Therefore Uniswap changes

```text
Pafter = 900
```

into

```text
Pafter = 1000
```

The swap stops exactly at the lower boundary.

Current state

```text
1000 ----------------------- 2000
↑
Current Price
```

---

## Step 4 — Determine How Much Input Was Consumed

Suppose the trader wanted to swap

```text
100 Token0
```

Moving from

```text
1500

↓

1000
```

only required

```text
60 Token0
```

Therefore

Trader supplied

```text
100 Token0
```

Pool consumed

```text
60 Token0
```

Remaining input

```text
40 Token0
```

The trader's entire input has **not** been consumed yet.

---

## Step 5 — Cross The Tick

Once the price reaches

```text
1000
```

the pool reaches the lower tick boundary.

Now Uniswap

- Removes liquidity positions ending here.
- Adds liquidity positions beginning here.
- Updates the active liquidity.

Suppose the next active range becomes

```text
800 ----------------------- 1000
```

The current price is now

```text
1000
```

---

## Step 6 — Continue The Swap

There is still

```text
40 Token0
```

remaining.

Now Uniswap starts another swap step.

Notice the important difference.

Previously

```text
Pbefore = 1500
```

Now

```text
Pbefore = 1000
```

because the previous swap step has already finished.

The formula is executed **again** using

```text
Current Price = 1000

New Active Liquidity

Remaining ΔX = 40
```

Suppose the formula now calculates

```text
Pafter = 920
```

Since

```text
800 < 920 < 1000
```

the price remains inside the new liquidity range.

The swap finishes.

# Child Analogy

Imagine driving a car.

You want to travel

```text
150 km
```

But your current road is only

```text
50 km
```

Can you continue driving after the road ends?

No.

Instead you

- Drive until the road ends.
- Enter the next road.
- Continue driving the remaining distance.

Uniswap behaves exactly the same way.

```text
Current Range

1000 ----------------------- 2000
              ↑
         Current Price = 1500

Trader wants to push the price to

900

↓

Formula calculates

900

↓

Pool says

"No.

This road ends at 1000."

↓

Stop at 1000

↓

Cross Tick

↓

Update Liquidity

↓

Continue with the remaining input

↓

Run the formula again
```

# Important Takeaway

The formula's only responsibility is

> **Calculate the theoretical next price using the current market price, current liquidity, and the input amount.**

It does **not**

- check liquidity boundaries,
- cross ticks,
- update liquidity,
- or continue the remaining swap.

Those responsibilities belong to the swap logic.

The formula simply answers

> **"If this liquidity stayed active for the entire swap, what would the next price be?"**

The swap logic then decides whether that price is actually reachable or whether it must stop at the current liquidity boundary first.
