# 🎯 What Is This Lesson Trying To Teach?

Before this lesson, we already knew two important equations.

For token X

```text
x = L/√Plower − L/√Pupper
```

For token Y

```text
y = L√Pupper − L√Plower
```

At first glance, it looks like this lesson is introducing completely new mathematics.

It isn't.

Instead, this lesson asks a completely different question using the exact same equations.

---

# Wait... Didn't We Already Learn These Equations?

Yes.

We already learned these equations during the Liquidity Math section.

However, while revising this lesson, I realized something important.

Initially, I mixed these equations up with Active Liquidity.

That is NOT what these equations calculate.

These equations calculate

> **The amount of token X and token Y corresponding to a liquidity position.**

They are NOT Active Liquidity formulas.

---

## These Equations Answer

Suppose Alice provides liquidity.

```text
Price Range

$4 ------------------------- $8

Liquidity = L
```

Question:

> How much token X belongs to this liquidity position?

Answer

```text
x = L/√Plower − L/√Pupper
```

Question

> How much token Y belongs to this liquidity position?

Answer

```text
y = L√Pupper − L√Plower
```

Notice something.

Nowhere are we calculating Active Liquidity.

We are calculating token amounts.

# Why Does Adding X Move Price Left?

We already learned this in previous lessons.

```text
More X enters

↓

X becomes less scarce

↓

Price decreases

↓

Price moves LEFT
```

Similarly

```text
More Y enters

↓

Y becomes less scarce

↓

Price increases

↓

Price moves RIGHT
```

Nothing new.

The only thing missing is

> Exactly HOW FAR does the price move?

That is what we will derive.

---

# Why Does The Lesson Use √Price Instead Of Price?

Notice something.

The final equations never end with

```text
Price
```

Instead they end with

```text
√Price
```

Why?

Because internally,

Uniswap V3 performs almost all price calculations using

```text
sqrtPriceX96
```

instead of normal price.

Therefore,

instead of converting everything back,

the protocol simply keeps everything in square-root form.

That is why every final equation ends with

```text
√Pafter
```

instead of

```text
Pafter
```

# Another Important Realization

Suppose two pools receive exactly the same swap.

Pool A

```text
Liquidity = 10
```

Pool B

```text
Liquidity = 1,000,000
```

Both receive

```text
ΔX = 100
```

Question

Which price moves more?

Answer

Pool A.

Why?

Because a small liquidity pool is much easier to move.

Large pools absorb swaps much more easily.

Exactly like slippage.
