

# Part 2 — Deriving The ΔX Formula



---

# What Does The Pool Already Know?

Suppose the pool currently knows(see part 1)

```text
Current Price = Pupper

Liquidity = L

Trader Added = ΔX
```

The only thing the pool does NOT know is

```text
New Price
```

which, for this derivation, is

```text
Plower
```

So the pool needs to solve for

```text
√Plower
```

---

# Which Equation Do We Already Have?

Earlier we learned

```text
x = L/√Plower − L/√Pupper
```

Originally,

this equation answered

> **How much token X exists inside this liquidity position?**

Now,

during the swap,

the amount of token entering is no longer some unknown

```text
x
```

It is literally

```text
ΔX
```

So we simply replace

```text
x

↓

ΔX
```

giving

```text
ΔX = L/√Plower − L/√Pupper
```

Notice something.

Nothing magical happened.

Same equation.

Different known value.

---

# Why Replace x With ΔX?

This confused me initially.

Earlier,

```text
x
```

meant

> Amount of token X inside the liquidity range.

Now,

during a swap,

the trader literally tells the pool

```text
I am swapping

ΔX
```

Therefore,

the pool already knows the amount of token entering.

So,

instead of writing

```text
x
```

we simply write

```text
ΔX
```

The mathematics has NOT changed.

Only the meaning of the known value changed.

# Step 2

Now notice something.

The left side has

```text

```

```text
ΔX
```

One is not.

Can we directly combine them?

No.

So,

```text

```

```text

```


Exactly the same idea.

# Final Formula — Adding ΔX

```text
√Pafter

=

L√Pbefore

/

(L + ΔX√Pbefore)
```

For THIS derivation

```text
Pbefore = Pupper

Pafter = Plower
```

Again,

this is ONLY because we intentionally started from the upper boundary.

The generalized equation later replaces them with

```text
Pbefore

↓

Pafter
```

so it works from any current price.

---

# Why Does The Formula Make Sense?

Suppose

```text
ΔX
```

becomes larger.

Then

```text
L + ΔX√Pbefore
```

becomes larger.

A larger denominator makes the entire fraction smaller.

A smaller

```text
√Price
```

means

a smaller price.

Exactly what we expected.

More X entering the pool pushes the price further LEFT.

---

# Removing ΔX

Now imagine the opposite.

Instead of ADDING X,

the trader REMOVES X.

Everything is identical.

Only

```text
+ΔX
```

becomes

```text
-ΔX
```

Final result

```text
√Pafter

=

L√Pbefore

/

(L − ΔX√Pbefore)
```

---

# General Formula

Now combine both cases.

```text
√Pafter

=

L√Pbefore

/

(L ± ΔX√Pbefore)
```

Use

```text
+
```

when adding ΔX.

Use

```text
-
```

when removing ΔX.

# ❓ Important Question We Discussed

At this point I realized something.

I asked:

> Wasn't `Pupper` supposed to be the LP's upper boundary?

Yes.

It absolutely is.

Normally

```text
Plower
```

and

```text
Pupper
```

are simply the LP's boundaries.

They are NOT the current market price.

So why is

```text
Pupper
```

suddenly treated as the current price?

Answer:

Only for the derivation.

The derivation intentionally starts at the upper boundary because it makes solving the equation much cleaner.

In reality,

during a swap,

the current price is usually somewhere inside the range.

---

# Another Question We Discussed

Suppose the current price is

```text
$6
```

instead of

```text
$8
```

Can we simply replace

```text
Pupper
```

with

```text
Pcurrent
```

inside

```text
x = L/√Plower − L/√Pupper
```

No.

Because that changes the meaning of the equation.

Originally,

the equation calculates

> **The amount of token X across the ENTIRE liquidity interval.**

If we replace

```text
Pupper
```

with

```text
Pcurrent
```

it now calculates

> **The amount of token X between the current price and the upper boundary.**

Completely different question.

So the original equation should NOT be modified unless we intentionally want that different meaning.

Later,

during actual swaps,

Uniswap DOES use formulas involving the current price.

Those are different formulas used by

```text
SqrtPriceMath.sol
```

and not the original liquidity equations.
