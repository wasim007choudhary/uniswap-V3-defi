# 📖 Discussion — Tick Crossing & Active Liquidity (Part 1)

---

## ❓ Question

Suppose we have three Liquidity Providers (LPs).

### Alice

```text
$4 ---------------- $7
```

### Bob

```text
                 $7 ---------------- $10
```

### Charlie

```text
                 $7 ------------------------ $15
```

Current market price:

```text
$4
```

The question is:

> **From 6.9 → 7, whose liquidity is being used?**
>
> **Once the pool reaches exactly Tick 7, is Alice's liquidity still used, or do Bob's and Charlie's liquidity become active immediately?**

---

# ✅ Answer

Excellent question.

This is where many people get confused.

The answer is:

- **For the movement up to Tick 7, Alice's liquidity is used.**
- **Once the pool crosses Tick 7, Alice's liquidity is removed.**
- **Bob's and Charlie's liquidity immediately become active.**

Let's visualize it.

---

# 📈 Liquidity Positions

Suppose we have:

```text
Alice:      $4 ---------------- $7

Bob:                         $7 ---------------- $10

Charlie:                    $7 ------------------------ $15
```

Current market price:

```text
$4
```

---

# 📍 Price = 6.9

Current active liquidity:

```text
✅ Alice

❌ Bob

❌ Charlie
```

---

# 📍 Price = 6.999999999

Still:

```text
✅ Alice

❌ Bob

❌ Charlie
```

Alice is still the **only active LP**.

Nothing has changed yet.

Even though the price is extremely close to Tick 7,

Alice is still providing all the active liquidity.

---

# 📍 Price Reaches Exactly Tick 7

This is the **Tick Crossing Event**.

The pool now executes the liquidity update.

Conceptually,

it performs:

```text
Remove Alice

Add Bob

Add Charlie
```

After the update:

```text
❌ Alice

✅ Bob

✅ Charlie
```

---

# 📍 Price = 7.000000001

Now the active liquidity is

```text
Bob + Charlie
```

Alice is no longer active.

---

# ❓ So What About Exactly Tick 7?

The important thing is that

> **Tick 7 is NOT an interval.**

It is a **boundary**.

Think of a doorway.

```text
Room A      |      Room B
            ^
          Door
```

If you're walking,

- Just before the door → you're inside **Room A**.
- As you pass through the door → you change rooms.
- Just after the door → you're inside **Room B**.

You never stand inside both rooms at the same time.

Tick 7 behaves exactly like that doorway.

---

# 📐 Another Way To Think About It

Alice owns the interval

```text
[4, 7)
```

Bob owns

```text
[7, 10)
```

Charlie owns

```text
[7, 15)
```

Conceptually,

the liquidity transition happens **at the boundary**.

So after crossing Tick 7,

```text
Remove Alice

Add Bob

Add Charlie
```

There isn't a phase where

- Alice,
- Bob,
- and Charlie

are all simultaneously active for the price interval beyond Tick 7.

---

# ❓ Follow-up Question

Question:

> **"At the moment it reaches 7 exactly, Alice's liquidity is not used?"**

### ✅ Precise Answer

The precise answer is:

- The movement **from below 7 up to 7** uses **Alice's liquidity**.
- **Crossing Tick 7** triggers the liquidity update.
- **Any movement beyond 7** uses **Bob's and Charlie's liquidity**.

That distinction—

> **moving to the boundary**
>
> versus
>
> **moving after crossing the boundary**

—is exactly what the `swap()` function's **Tick Crossing Logic** handles.

# ❓ Follow-up Question

A follow-up question was asked:

> **"I mean from 6.9 → 7, Alice's liquidity is used, right?**
>
> **And now from 7 onwards, with the very first movement, it's Bob's liquidity, etc.?"**

### ✅ Answer

Yes.

**That's exactly right.**

The key is to think in terms of **price intervals**, not just the tick itself.

---

# 📈 Liquidity Positions

Suppose we have:

```text
Alice:      $4 ---------------- $7

Bob:                         $7 ---------------- $10

Charlie:                    $7 ------------------------ $15
```

Current market price:

```text
$4
```

---

# 📍 From $4 → $7

Question:

> **Who provides liquidity?**

Answer:

```text
✅ Alice
```

Graphically,

```text
$4 ─────────────────────────► $7

Using Alice's Liquidity
```

Every tiny movement

```text
4.1

4.2

4.3

...

6.9

6.99

6.99999
```

uses **Alice's liquidity**.

Alice remains the active liquidity provider for the **entire movement up to Tick 7**.

---

# 📍 At Exactly Tick 7

The pool reaches the initialized tick.

This is **not another price interval.**

Instead,

it's an **event**.

The event is:

```text
Reached Tick 7

↓

Cross Tick

↓

Update Active Liquidity
```

The pool removes LPs ending at this tick

and adds LPs starting at this tick.

Conceptually,

the pool performs:

```text
Remove Alice

+

Add Bob

+

Add Charlie
```

---

# 📍 Immediately After Crossing

Now the price becomes

```text
7.0000001
```

Question:

> **Who provides liquidity now?**

Answer:

```text
✅ Bob

✅ Charlie

❌ Alice
```

Now every movement

```text
7.00001

↓

7.1

↓

7.5

↓

8
```

uses

```text
Bob + Charlie
```

Alice is no longer active.

---

# 📊 Visual Timeline

```text

        Alice                  Alice         Cross Tick            Bob + Charlie
                                              ▲
                                   Liquidity is updated here
```

Notice this timeline carefully.

Movement

```text
6.9

↓

7
```

still uses

```text
Alice
```

The pool then performs the Tick Crossing Event.

Only **after** that crossing

```text
Bob + Charlie
```

---

# 🏃 Child Analogy — Relay Race

Think of a relay race.

```text
Alice 🏃────────🏁────────Bob 🏃
                 ^
            Handover Point
```

Before the handover,

Alice is running.

At the handover,

Alice gives the baton to Bob.

Immediately afterwards,

Bob runs.

The baton isn't carried by both after the handover.

Tick 7 is exactly that handover point.

---

# ✅ Final Confirmation

So your understanding is correct.

✅ From **6.9 → 7**, the movement uses **Alice's liquidity**.

✅ Crossing Tick 7 updates the active liquidity.

✅ From **7 onward** (the very first infinitesimal movement beyond 7),

the movement uses

```text
Bob + Charlie
```

---

The distinction is:

```text
Move To The Boundary

↓

Continue After The Boundary
```

More specifically,

```text

↓

Update Active Liquidity

```

That distinction—

> **moving to the boundary**
>
> versus
>
> **moving after crossing the boundary**
