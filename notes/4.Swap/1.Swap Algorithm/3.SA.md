# What Happens Inside The While Loop?

The lesson now zooms into the while loop.

Instead of looking at the overall swap,

we now focus on **what happens during one iteration** of the loop.

Think of each iteration as **one small step of the swap**.

Instead of processing the entire swap at once,

the pool processes a small portion,

updates everything,

then decides whether another iteration is needed.

---

# amountSpecifiedRemaining

The lesson introduces a local variable called

```text
amountSpecifiedRemaining
```

It is initialized using

```text
amountSpecified
```

Suppose the user wants to swap

```text
1000 USDC
```

Initially,

```text
amountSpecifiedRemaining = 1000
```

Nothing has been swapped yet.

---

## What Does It Represent?

Think of it as

> **How much swap is still left to perform?**

It is like a progress tracker.

At the beginning

```text

```

After some swapping

```text

```

Later

```text
300 left
```

Eventually

```text
0 left
```

At that moment,

the swap is complete.

# The Current Price

The lesson says

the current square root price is stored in a local variable.

Why?

Because the price changes during the swap.

Suppose the current price is

```text
$4
```

Initially

```text
Current Price = $4
```

After some trading

```text
Current Price = $4.10
```

Later

```text
Current Price = $4.35
```

Later

```text
Current Price = $4.80
```

The algorithm always needs to know

where the current price is **right now**.

That's why it stores it locally.

# Calculating amountIn, amountOut and Fee

Now the pool knows

Current Price

and

Next Price.

Between these two prices,

the pool calculates three things.

---

## 1. amountIn

This answers

> **How many input tokens came into the pool?**

---

## 2. amountOut

This answers

> **How many output tokens leave the pool?**

---

## 3. Fee

This answers

> **How much fee should the pool collect?**

So every iteration computes

```text
Input

↓

Output

↓

Fee
```

# Crossing Into Another Liquidity Range

Now let's connect this to concentrated liquidity.

Suppose

Alice provides liquidity between

```text
$3 ---------------- $7
```

Bob provides liquidity between

```text
$7 ---------------- $10
```

Current price

```text
$4
```

Initially,

the swap only uses

Alice's liquidity.

As trading continues,

the price moves.

```text
$4

↓

$5

↓

$6

↓

$7
```

When the price reaches

```text
$7
```

Alice's range has ended.

Now the pool crosses into Bob's range.

Notice something important.

The pool did **NOT** move into another pool.

There is still only **one Uniswap V3 Pool.**

What changed is

which liquidity positions are active.

Before crossing

```text
Active Liquidity

=

Alice
```

After crossing

```text
Active Liquidity

=

Bob
```

If many LPs begin or end at that tick,

the pool updates all of them accordingly.

# Summary

Inside every iteration,

the pool performs the same sequence of work.

```text
Current Price

↓

Find Next Tick

↓

Calculate sqrtPriceNext

↓

Calculate amountIn

↓

Calculate amountOut

↓

Calculate Fee

↓

Update Current Price

↓

Still More Swap Left?

↓

Yes → Repeat

No → Exit Loop
```

The swap slowly moves through the pool,

one small step at a time,

until either:

- all requested tokens have been swapped,

or

- the specified price limit has been reached.
