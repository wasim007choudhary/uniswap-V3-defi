# Uniswap V3 — Ticks, Tick Boundaries & `liquidityNet`

## 1. Ticks vs Prices

A **tick** is simply a **price point** on the global price axis.

Every tick corresponds to exactly one price.

```text
Price Axis

0.90      0.95      1.00      1.05      1.10
  │          │          │          │
Tick90    Tick95    Tick100   Tick105
```

The relationship is:

```
price = 1.0001^tick
```

So,

```
Tick 10 → Price A
Tick 20 → Price B
Tick 30 → Price C
```

---

# 2. Pa and Pb are NOT ticks

Many people confuse these.

Ticks are **global price points**.

Pa and Pb are **prices corresponding to an LP's chosen boundaries**.

Suppose an LP chooses

```
tickLower = 10
tickUpper = 20
```

Then

```
tickLower  → Pa

tickUpper  → Pb
```

Graphically,

```text
Price Axis

Pa --------------------------- Pb
│                              │
tickLower                  tickUpper
```

So,

```
tickLower ↔ Pa

tickUpper ↔ Pb
```

Current market price

```
currentTick ↔ P
```

# 6. What happens when price moves inside the range?

Suppose current price

```
Tick16
```

```text
10 ----------------16----------------20
```

Does liquidity change?

No.

Nothing happens.

Why?

Because we have not crossed an initialized tick.

Current liquidity remains

```
10
```

Only when price reaches

```
Tick20
```

does liquidity change.

---

# 7. What is liquidityNet?

Each initialized tick stores

```
How should liquidity change when this tick is crossed?
```

That stored change is

```
liquidityNet
```

It is NOT the tick.

It is metadata stored at the tick.

Think of it like

```text
Tick10

Price = 10
liquidityNet = +10

-----------------------

Tick20

Price = 20
liquidityNet = -10
```

Tick 20 is NOT negative.

Only

```
liquidityNet
```

is negative.

---

# 8. Why +10 and -10?

Suppose

```
tickLower = 10
tickUpper = 20
Liquidity = 10
```

Liquidity starts at tick10.

So

```
tick10

liquidityNet += 10
```

Liquidity ends at tick20.

So

```
tick20

liquidityNet -= 10
```

Final values

```text
Tick10

liquidityNet = +10

Tick20

liquidityNet = -10
```

---

# 9. Why negative?

Because

```
Tick20

means

"My liquidity ends here."
```

So whenever price crosses Tick20 moving right,

the active liquidity should decrease.

Hence

```
-10
```

Nothing imaginary.

This value is literally stored inside the pool.

# 10. Liquidity Update Formula

## When minting

Suppose LP provides

```
tickLower = A

tickUpper = B

Liquidity = L
```

Store

```
tickLower.liquidityNet += L

tickUpper.liquidityNet -= L
```

---

## Moving RIGHT (price increasing)

Whenever price crosses an initialized tick,

```
currentLiquidity

=

currentLiquidity

+

liquidityNet
```

Formula

```
Lnew = Lcurrent + liquidityNet
```

Example

```
Current Liquidity = 10

Tick20

liquidityNet = -10
```

Cross

```
10 + (-10)

=

0
```

LP becomes inactive.

---

## Moving LEFT (price decreasing)

Whenever price crosses an initialized tick,

```
currentLiquidity

=

currentLiquidity

-

liquidityNet
```

Formula

```
Lnew = Lcurrent - liquidityNet
```

Example

Suppose price is above Tick20.

Current Liquidity

```
0
```

Cross Tick20 moving left.

```
0 - (-10)

=

10
```

Liquidity becomes active again.

---

# Memory Trick

Moving Right

```
L += liquidityNet
```

Moving Left

```
L -= liquidityNet
```

# Key Takeaways

- Every tick is a price point.
- `tickLower` and `tickUpper` define an LP's active range.
- `Pa` and `Pb` are the prices corresponding to `tickLower` and `tickUpper`.
- Liquidity is active only between `Pa` and `Pb`.
- Every mathematical tick exists, but only boundary ticks are initialized.
- Intermediate ticks (11, 12, 13...) are just price points unless some LP starts or ends there.
- `liquidityNet` is stored only at initialized ticks.
- At `tickLower`, store `+L`.
- At `tickUpper`, store `-L`.
- Moving right: `currentLiquidity += liquidityNet`.
- Moving left: `currentLiquidity -= liquidityNet`.
- The pool never scans all LPs. Crossing an initialized tick and applying `liquidityNet` is enough to update the active liquidity instantly.
