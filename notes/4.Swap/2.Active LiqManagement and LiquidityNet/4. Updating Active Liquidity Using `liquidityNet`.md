# 🎯 What Is This Lesson Trying To Teach?

The previous lesson taught us

> **How crossing one initialized tick updates the Active Liquidity.**

This lesson answers a different question.

Suppose a swap is so large that the price keeps moving.

Instead of crossing **one** initialized tick,

it crosses

```text
Tick A

↓

Tick B

↓

Tick C

↓

Tick D
```

How does the pool keep updating the Active Liquidity?

Does it recalculate every Liquidity Provider again?

**No.**

Instead,

every time the price crosses an initialized tick,

the pool simply applies that tick's stored `liquidityNet`.

This lesson shows how that process works.

# What Is Tick Delta?

The lesson introduces two new terms.

```text
Initial Tick
```

and

```text
Current Tick
```

The difference between them is called

```text
Tick Delta
```

It simply measures

> **how far the price has moved from where the swap started.**

Example:

Suppose the swap starts at

```text
Tick100
```

After the swap,

the current tick becomes

```text
Tick108
```

Then

```text
Tick Delta

=

108 - 100

=

+8
```

If instead,

the price falls to

```text
Tick94
```

then

```text
Tick Delta

=

94 - 100

=

-6
```

Positive Tick Delta means

> **Price increased.**

Negative Tick Delta means

> **Price decreased.**

# Why Does Tick Delta Matter?

The farther the price moves,

the more initialized ticks it may cross.

Suppose the initialized ticks are

```text
Tick100

↓

Tick105

↓

Tick110

↓

Tick115
```

If the swap ends at

```text
Tick102
```

then no initialized tick has been crossed.

The Active Liquidity stays the same.

---

Now suppose the swap reaches

```text
Tick117
```

The price has crossed

```text
Tick105

↓

Tick110

↓

Tick115
```

Each crossing requires the Active Liquidity to be updated.

# Worked Example 1 — Single LP

Suppose there is only one Liquidity Provider.

```text
tickLower ------------------------- tickUpper

          Liquidity = 4
```

The current price is inside the range.

Therefore,

```text
Current Active Liquidity = 4
```

---

## Price Moves Right (→)

The price increases until it crosses

```text
tickUpper
```

Remember,

the upper tick stores

```text
liquidityNet = -4
```

The direction is

```text
+1
```

Apply the formula.

```text
Next Liquidity

=

Current Liquidity

+

(Direction × liquidityNet)

=

4

+

(+1 × -4)

=

0
```

The Active Liquidity becomes

```text
0
```

because Alice's liquidity is no longer active.

---

## Price Moves Left (←)

Let's reset.

Again,

```text
Current Active Liquidity = 4
```

Now the price moves left until it crosses

```text
tickLower
```

Remember,

the lower tick stores

```text
+4
```

The direction is

```text
-1
```

Apply the formula.

```text
4

+

(-1 × 4)

=

0
```

Again,

the Active Liquidity becomes

```text
0
```

Exactly what we expect.

# Worked Example 2 — Multiple LPs

Now suppose multiple Liquidity Providers overlap.

After adding all active liquidity,

the pool currently has

```text
Current Active Liquidity = 13
```

Notice that

the pool does **not**

recalculate every LP.

It simply starts with

```text
13
```

---

## First Tick Crossing

The price increases.

Therefore,

```text
Direction = +1
```

The initialized tick stores

```text
liquidityNet = -10
```

Apply the formula.

```text
Next Liquidity

=

13

+

(+1 × -10)

=

3
```

Now,

```text
Current Active Liquidity = 3
```

---

## The Swap Continues

The swap hasn't finished yet.

The price keeps moving.

Eventually,

it reaches another initialized tick.

That tick stores

```text
liquidityNet = -3
```

Apply the same formula again.

```text
Next Liquidity

=

3

+

(+1 × -3)

=

0
```

Now,

```text
Current Active Liquidity = 0
```

Notice something.

The formula never changed.

Only the inputs changed.

# 🎯 Final Mental Model

Whenever the current price crosses an initialized tick,

the pool performs four simple steps.

```text
Current Active Liquidity

↓

Cross Initialized Tick

↓

Read liquidityNet

↓

Apply Liquidity Update Formula

↓

New Active Liquidity

↓

Continue Swap
```

If another initialized tick is crossed,

the process repeats.

The pool never recalculates every Liquidity Provider.

It simply applies the stored `liquidityNet` at each initialized tick.

That elegant design allows Uniswap V3 to process swaps efficiently, even with millions of liquidity positions.

# 📝 Key Takeaways

- This lesson extends the previous `liquidityNet` lesson.
- A large swap may cross multiple initialized ticks.
- Every initialized tick crossed may change the current Active Liquidity.
- `Tick Delta` measures how far the price moved from the starting tick.
- The liquidity update formula is applied at every initialized tick.
- The formula itself never changes—only the inputs do.
- Active Liquidity is updated continuously throughout a swap.
- This repeated update process is exactly what the `while` loop inside `UniswapV3Pool.swap()` performs.
- Understanding this lesson makes the upcoming `Tick.cross()` and `swap()` implementations much easier to follow.
