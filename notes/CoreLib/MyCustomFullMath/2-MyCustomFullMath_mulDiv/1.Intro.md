# 2. Why `mulDiv()` Exists

Suppose we want to compute:

```solidity
result = (x * y) / denominator;
```

This seems simple.

Unfortunately, Solidity has a limitation.

Every integer is at most:

```
uint256
```

which means it can only store numbers between

```
0

↓

2²⁵⁶ − 1
```

Now imagine:

```
x = huge uint256
y = huge uint256
```

Their product may require:

```
512 bits
```

to store.

Even if the final answer after division fits inside 256 bits,

the multiplication happens first.

That multiplication can overflow.

Example:

```
Huge × Huge

↓

Needs 512 bits

↓

uint256 cannot store it

↓

Overflow
```

So the following code is **not always safe**:

```solidity
result = (x * y) / denominator;
```

The multiplication itself may overflow before the division ever happens.

---

# The Goal of `mulDiv()`

The purpose of `mulDiv()` is very simple:

Compute

```
floor(x × y / denominator)
```

without ever losing precision,

while also avoiding overflow.

Notice something important.

The goal is **not**

```
Compute x × y
```

The goal is

```
Compute the final quotient safely.
```

Those are two completely different problems.

---

# Why Is This So Important?

Many DeFi protocols constantly perform calculations like:

- Token swaps
- LP share calculations
- Interest calculations
- Fee distribution
- Liquidity accounting

Those calculations often multiply two huge numbers before dividing.

Without `mulDiv()`,

either:

- overflow happens,

or

- developers lose precision by dividing early.

Neither is acceptable for financial software.

That is why OpenZeppelin, Uniswap V3, Aave, Curve, and many other protocols rely on this algorithm.
