# 16. Newton-Raphson — Refining the Modular Inverse

After computing the initial 4-bit seed,

OpenZeppelin repeatedly executes the same line.

```solidity
inverse *= 2 - denominator * inverse;
```

It does this six times.

```solidity
inverse *= 2 - denominator * inverse; // inverse mod 2⁸
inverse *= 2 - denominator * inverse; // inverse mod 2¹⁶
inverse *= 2 - denominator * inverse; // inverse mod 2³²
inverse *= 2 - denominator * inverse; // inverse mod 2⁶⁴
inverse *= 2 - denominator * inverse; // inverse mod 2¹²⁸
inverse *= 2 - denominator * inverse; // inverse mod 2²⁵⁶
```

Every line is identical.

The only thing that changes is

the accuracy.

# The Big Idea

Instead of finding a completely new inverse,

Newton-Raphson improves the one we already have.

Think of it like this.

```text
Current Guess

↓

Measure how far it is from perfect

↓

Compute a correction

↓

Apply the correction

↓

Get a better guess

↓

Repeat
```

Notice something.

We are **not searching again**.

We are simply improving the existing guess.

```text

```



# The Formula Knows Which Direction To Move

If the inverse is

too small

```text
↓

Correction > 1

↓

Increase the inverse
```

If the inverse is

too large

```text
↓

Correction < 1

↓

Decrease the inverse
```

There is no

```solidity
if (...)
```

statement.

The mathematics automatically moves the guess in the correct direction.

# But Solidity Doesn't Use Decimals

Everything above was only intuition.

The real implementation works entirely with

```text
uint256
```

using modular arithmetic.

Instead of ordinary numbers,


The mathematical theorem guarantees

# Why Doesn't It Skip The Correct Answer?

One of the biggest questions is:

> "If we keep doubling the accuracy, won't we jump over the correct answer?"

No.

This is not a search algorithm.

It is an improvement algorithm.

Imagine a puzzle.

Initially

```text
□□□□□□□□□□□□□□□□□□□□□□□□□□□□FGHI
```

Only the last

```text
4
```

pieces are correct.

After one iteration,

```text
□□□□□□□□□□□□□□□□□□□□□□□□DEFGHI
```

Now the last

```text
8
```

pieces are correct.

After another

```text
□□□□□□□□□□□□BCDEFGHI
```

Now

```text
16
```

pieces are correct.

Notice something.

The previous correct pieces never disappear.

Each iteration simply discovers more.

# Key Takeaways

* Newton-Raphson does **not** search for a new inverse.
* It repeatedly improves the existing inverse.
* Each iteration:

  * Measures how far the current guess is from perfect.
  * Computes a correction factor.
  * Applies that correction.
* If the guess is too small, the correction factor becomes greater than `1`.
* If the guess is too large, the correction factor becomes less than `1`.
* Existing correct bits are never lost.
* Every iteration doubles the number of correct bits:

  ```
  4 → 8 → 16 → 32 → 64 → 128 → 256
  ```
* After six iterations, the modular inverse is fully correct for all 256 bits.
