# Uniswap V3 — Amounts of Tokens Between Price Ranges

Up until now, we've derived two very important equations:

```text
X = L / √P
```

```text
Y = L√P
```

where:

- `L` = Liquidity
- `P` = Current Price

These equations tell us **how many Token X and Token Y exist at a single price.**

However, this lesson asks a different question.

Instead of asking:

> **"How much Token X is at one price?"**

it asks:

> **"How much Token X exists between two prices?"**

The same question is asked for Token Y.

---

# The Goal Of This Lesson

Suppose we have a Position:

```text
Pa ----------- P ----------- Pb
```

Where:

- `Pa` = Lower Price
- `P` = Current Price
- `Pb` = Upper Price

We want to answer two questions.

**Question 1**

How much **Token X** exists between:

```text
Current Price

↓

Upper Price
```

**Question 2**

How much **Token Y** exists between:

```text
Lower Price

↓

Current Price
```

Notice that we are **measuring a section of our Position**, not the entire Position.

---

# We Already Know The Token Amount At One Price

Earlier we proved:

```text
X = L / √P
```

and

```text
Y = L√P
```

These equations tell us the amount of tokens at **one specific price**.

For example,

Suppose:

```text
Liquidity = 100
```

Current price:

```text
P = 25
```

Then:

```text
√25 = 5
```

Token X:

```text
100 / 5

=

20
```

Token Y:

```text
100 × 5

=

500
```

These numbers represent the token amounts **at exactly one price**.

---

# This Lesson Asks A Different Question

Instead of asking:

> "How much Token X exists at one price?"

it asks:

> **"How much Token X exists between two prices?"**

These are two completely different questions.

---

# Child Analogy — Measuring A Line


> How long is the line between:


To find the amount **between** them,

we simply subtract.

# Calculating Token X Between Two Prices

Our Position looks like this:

```text
Pa ----------- P ----------- Pb
```

Remember:

As price increases,

Token X is gradually converted into Token Y.

So the remaining Token X exists between:

```text
Current Price

↓

Upper Price
```

Graphically:

```text
Pa ----------- P ================= Pb
               ↑                  ↑
         Current Price       Upper Price

      Remaining Token X
```

---

# Step 1 — Token X At The Current Price

From our previous derivation:

```text
X = L / √P
```

---

# Step 2 — Token X At The Upper Price

Replace:

```text
P
```

with:

```text
Pb
```

Result:

```text
L / √Pb
```

---

# Step 3 — Find The Difference

Just like measuring a ruler,

we subtract.

Current amount:

```text
L / √P
```

minus

Upper boundary amount:

```text
L / √Pb
```

Result:

```text
X

=

L / √P

-

L / √Pb
```

This is the amount of Token X remaining between the current price and the upper price.

---

# Important Discussion — Why Isn't It Upper Minus Current?

A question came up during the lesson.

Since:

```text
Pb > P
```

shouldn't the equation be:

```text
L / √Pb

-

L / √P
```

The answer is:

> **No.**

This is because we are **not subtracting the prices.**

We are subtracting the **token amounts at those prices.**

Those are completely different things.

---

# Example

Suppose:

```text
L = 100
```

Current price:

```text
P = 25

√25 = 5
```

Upper price:

```text
Pb = 100

√100 = 10
```

Current Token X:

```text
100 / 5

=

20
```

Upper Token X:

```text
100 / 10

=

10
```

Now ask:

How much Token X exists between them?

Simply:

```text
20

-

10

=

10
```

If we reversed the subtraction:

```text
10

-

20

=

-10
```

We would get a **negative amount of tokens**, which makes no physical sense.

So the correct equation is:

```text
L / √P

-

L / √Pb
```

because we're subtracting token amounts,

not prices.


For the Token X equation,



```text

-

```

# Additional Discussion — How Many Tokens Can Be Traded Before Crossing a Price Boundary?

While studying the equations, an important question came up.

We learned that:

```text
Token X

=

L / √P

-

L / √Pb
```

and

```text
Token Y

=

L√P

-

L√Pa
```

These equations tell us how many tokens exist **between two prices**.

But they can also answer another very useful question.

> **How many tokens can be traded before the current price reaches the next price boundary?**

This is one of the key ideas behind how swaps work in Uniswap V3.

---

# Case 1 — Moving the Price Upward Towards `Pb`

Suppose our Position is:

```text
Pa ----------- P ----------- Pb
```

The current price is inside the Position.

Now suppose traders keep swapping **Token Y into the pool** to buy **Token X**.

As more Token Y enters the pool:

- The pool gives out Token X.
- The current price moves upward.
- The remaining Token X gradually decreases.

Eventually, the current price reaches:

```text
Pb
```

At this point, every Token X inside this price range has been consumed.

The amount of Token X that existed between:

```text
P

↓

Pb
```

is exactly:

```text
L / √P

-

L / √Pb
```

Therefore,

the maximum amount of Token X that can be traded **without crossing `Pb`** is:

```text
L / √P

-

L / √Pb
```

Trading **exactly** this amount moves the current price to:

```text
Pb
```

but **not beyond it.**

---

# Child Analogy — Drinking Water From a Bottle

Imagine a bottle contains exactly:

```text
1 Liter
```

If you drink:

```text
1 Liter
```

the bottle becomes:

```text
Empty
```

You have reached the end of the bottle.

But you have **not** drunk past the bottle.

Exactly the same thing happens here.

Trading exactly:

```text
L / √P

-

L / √Pb
```

uses up all the Token X inside this price range.

The current price reaches:

```text
Pb
```

but does not cross it.

---

# What If We Want To Cross `Pb`?

Now suppose we trade **more** than:

```text
L / √P

-

L / √Pb
```

For example:

```text
(L / √P - L / √Pb)

+

ε
```

where:

```text
ε
```

is an extremely small positive amount.

Now the current price attempts to move beyond:

```text
Pb
```

At this point:

```text
0 Token X

100% Token Y
```

This Position has been completely exhausted.

If another liquidity Position begins at `Pb`,

the swap simply continues into that next Position.

---

# Child Analogy — Walking Across a Room

Imagine you're standing inside a room.

```text
Door ---------------- You ---------------- Wall
```

Walking until you touch the wall means you've reached the end of the room.

Walking one more step means you've left the room and entered the next one.

Exactly the same thing happens here.

Trading exactly the calculated amount reaches:

```text
Pb
```

Trading anything more crosses into the next liquidity range.

# The Two Ways To Interpret These Equations

Originally, these equations answered:

> **How many tokens exist between two prices?**

```text
Token X

=

L / √P

-

L / √Pb
```

```text
Token Y

=

L√P

-

L√Pa
```

But they also answer another equally important question:

> **How many tokens can be traded before the current price reaches the next price boundary?**

So these equations have **two interpretations**.

### Interpretation 1 — Liquidity

They tell us how much Token X or Token Y exists inside a price interval.

### Interpretation 2 — Swap Capacity

They tell us the maximum amount that can be swapped before the current price reaches the next Tick (price boundary).

This second interpretation becomes extremely important when studying the implementation of **Uniswap V3's `swap()` function**, because the protocol repeatedly calculates how far the current price can move before it reaches the next initialized Tick.

---

# Key Takeaways

- The equations measure both:
  - The amount of tokens between two prices.
  - The maximum amount that can be swapped before reaching the next price boundary.
- Trading exactly:
  ```text
  L / √P - L / √Pb
  ```
  moves the current price exactly to:
  ```text
  Pb
  ```
- Trading more than that amount causes the price to cross `Pb` and continue into the next liquidity Position.
- Trading exactly:
  ```text
  L√P - L√Pa
  ```
  moves the current price exactly to:
  ```text
  Pa
  ```
- Trading more than that amount causes the price to cross `Pa` and continue into the next liquidity Position.
- Every liquidity Position has a finite amount of Token X and Token Y available within its own price range.
- Once that liquidity is exhausted, Uniswap V3 automatically continues the swap using the next initialized liquidity range.

# Additional Discussion — How Many Tokens Exist Between `Pa` and `Pb`?

While studying the generalized equations, another important question came up.

Suppose we have a liquidity Position:

```text
Pa ------------------------- Pb
```

A natural question is:

> **How many Token X and Token Y exist between `Pa` and `Pb`?**

At first glance, this seems like a simple question.

However,

it actually **does not have a single answer.**

---

# Why Doesn't It Have One Answer?

The reason is simple.

The amounts of **Token X** and **Token Y** continuously change as the **current market price (`P`)** moves.

Although the Position's price range stays the same,

its token composition is always changing.

So simply knowing:

```text
Pa

and

Pb
```

is **not enough**.

We must also know:

```text
Current Price (P)
```

---

# Example 1

Suppose our Position is:

```text
Pa ------------------------- Pb
```

Now suppose the current price is close to the lower boundary.

```text
Pa ----- P ------------------ Pb
```

Most of the Position is still Token X.

For example:

```text
80 Token X

20 Token Y
```

---

# Example 2

Now suppose the current price moves higher.

```text
Pa -------------- P -------- Pb
```

Some Token X has already been converted into Token Y.

Now the Position might contain:

```text
30 Token X

70 Token Y
```

---

# Example 3

Now suppose the current price reaches the upper boundary.

```text
Pa ------------------------- Pb = P
```

The Position becomes:

```text
0 Token X

100% Token Y
```

---

# Notice Something Important

During all three examples,

the Position never changed.

It was always:

```text
Pa ------------------------- Pb
```

Only the **current market price** changed.

Yet the token amounts changed completely.

This is why the question:

> **"How many tokens are there between `Pa` and `Pb`?"**

cannot be answered unless we also know:

```text
Current Price (P)
```

---

# Child Analogy — A Glass of Water

Imagine a glass.

```text
Top
│
│
│
│
Bottom
```

You tell someone:

> **"The glass is 20 cm tall."**

Can they tell you how much water is inside?

No.

They also need to know:

> **Where is the water level?**

For example,

if the water level is here:

```text
████████
```

the glass is almost full.

If the water level is here:

```text
██
```

the glass is almost empty.

Notice that the size of the glass never changed.

Only the water level changed.

Exactly the same thing happens in Uniswap V3.

- `Pa` and `Pb` define the **container** (the liquidity range).
- `P` (the current price) tells us how much of that container is currently Token X and how much is Token Y.

Without knowing `P`,

we cannot know the current token amounts.

---

# Can We Calculate Anything Using Only `Pa` and `Pb`?

Yes.

Although we cannot calculate the **current** token amounts,

we **can** calculate the **maximum possible** amount of each token.

---

## Maximum Token X

Suppose the current price moves below the lower boundary.

```text
P

↓

Pa ------------------------- Pb
```

The Position becomes:

```text
100% Token X

0 Token Y
```

Now the Position contains the largest amount of Token X it can ever have.

That amount is:

```text
Xmax = L / √Pa - L / √Pb
```

---

## Maximum Token Y

Now suppose the current price moves above the upper boundary.

```text
Pa ------------------------- Pb

↓

P
```

The Position becomes:

```text
0 Token X

100% Token Y
```

Now the Position contains the largest amount of Token Y it can ever have.

That amount is:

```text
Ymax = L√Pb - L√Pa
```

---

# Why Doesn't The Current Price Appear Here?

Notice something interesting.

Earlier,

our equations always used the current price.

For example:

```text
X = L / √P - L / √Pb
```

```text
Y = L√P - L√Pa
```

But in the maximum token equations,

the current price disappears.

Why?

Because in these special cases,

the current price has already reached one of the boundaries.

For maximum Token X:

```text
P ≤ Pa
```

The Position is already:

```text
100% Token X
```

For maximum Token Y:

```text
P ≥ Pb
```

The Position is already:

```text
100% Token Y
```

So the boundary itself completely determines the answer.

---

# Summary

The question:

> **"How many tokens exist between `Pa` and `Pb`?"**

is incomplete.

A better question is:

> **"How many tokens exist between `Pa` and `Pb` at the current market price `P`?"**

Only then can we calculate the current amounts of Token X and Token Y.

If we only know:

```text
Pa

and

Pb
```

we cannot determine the current token composition,

because it continuously changes as the market price moves.

However,

we can still calculate the **maximum possible** Token X and Token Y that the Position can ever contain.

---

# Key Takeaways

- Knowing only:
  ```text
  Pa
  ```
  and
  ```text
  Pb
  ```
  is **not enough** to determine the current token amounts.
- The current market price (`P`) is also required.
- As `P` moves:
  - Token X continuously decreases.
  - Token Y continuously increases.
- The Position's price range never changes, but its token composition does.
- The maximum Token X occurs when:
  ```text
  P ≤ Pa
  ```
  giving:
  ```text
  Xmax = L / √Pa - L / √Pb
  ```
- The maximum Token Y occurs when:
  ```text
  P ≥ Pb
  ```
  giving:
  ```text
  Ymax = L√Pb - L√Pa
  ```
- Think of `Pa` and `Pb` as the size of a container, and `P` as the water level inside it. The container stays the same, but the contents change continuously.

# Example 1 — Token X Between `Pa` and `P`

Suppose we have:

```text
Pa ---------------- P ---------------- Pb
```

> **How much Token X exists between `Pa` and the current price `P`?**

```text
Pa ---------------- P
```

```text
Plower = Pa

Pupper = P
```

```text
X = L / √Plower - L / √Pupper
```

gives:

```text
X = L / √Pa - L / √P
```

This represents the amount of Token X contained between the lower boundary and the current market price.

> **How much Token X exists between the current price and the upper boundary?**

Our interval is:

```text
P ---------------- Pb
```

Here:

```text
Plower = P

Pupper = Pb
```

Substituting gives:

```text
X = L / √P - L / √Pb
```

This is exactly the equation we originally derived.

---

# Example 3 — Token Y Between `Pa` and `P`

Now consider Token Y.

Question:

> **How much Token Y exists between the lower boundary and the current price?**

The interval is:

```text
Pa ---------------- P
```

Here:

```text
Plower = Pa

Pupper = P
```

Substituting into:

```text
Y = L√Pupper - L√Plower
```

# The Beautiful Symmetry

For **any two prices**:

```text
A ---------------- B
```

where:

```text
A < B
```

Token X is always:

```text
X = L / √A - L / √B
```

Token Y is always:

```text
Y = L√B - L√A
```

Notice that the equations never change.

Only the values of the endpoints change.

This is why the equations were generalized.

Instead of memorizing separate equations for every situation,

we only need to remember one general formula for Token X and one general formula for Token Y.
