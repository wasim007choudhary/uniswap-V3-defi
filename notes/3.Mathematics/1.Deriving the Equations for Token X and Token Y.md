# Uniswap V3 — Deriving the Equations for Token X and Token Y

Up until now, we've learned about:

- Tick
- Price (`P`)
- `sqrtPriceX96`
- Liquidity (`L`)

Now we reach one of the most important parts of Uniswap V3 mathematics.

Our goal is to answer questions like:

- **How much Token X is currently in a Position?**
- **How much Token Y is currently in a Position?**
- **Given the current Liquidity (`L`) and Price (`P`), can we calculate the token amounts?**

The answer is **Yes**, and that's exactly what we're going to derive.

---

# First Question

Suppose someone tells us:

```text
Liquidity = 500

Price = 4
```

Can we immediately answer:

```text
How much Token X is there?

How much Token Y is there?
```

Not yet.

That's what we're about to derive.

---

# Why Was This Easy in Uniswap V2?

Suppose a Uniswap V2 Pool contains:

```text
100 WETH

300,000 USDC
```

Immediately we know:

```text
X = 100

Y = 300000
```

Finding the price is trivial.

```text
Price

=

Y / X

=

300000 / 100

=

3000
```

Everything needed is stored directly inside the Pool.

---

# Why Doesn't This Work in Uniswap V3?

Remember what we learned about concentrated liquidity.

Suppose:

Alice provides liquidity between:

```text
2900

↓

3100
```

Bob chooses:

```text
2500

↓

3500
```

Charlie chooses:

```text
3200

↓

4000
```

Every Position has its own:

- Token X
- Token Y
- Liquidity
- Price Range

Unlike Uniswap V2,

there is no single pair of values:

```text
X

Y
```

for the entire Pool.

Different Positions hold different token amounts depending on where the current price is.

So simply looking at the total amount of Token X and Token Y inside the contract no longer tells us the current spot price.

---

# What Does Uniswap V3 Store Instead?

Instead of storing:

```text
Token X

Token Y
```

Uniswap V3 stores:

```text
Current Liquidity (L)
```

and

```text
Current Price (P)
```

From these two values,

the protocol can calculate:

```text
Token X

Token Y
```

whenever needed.

This is one of the biggest architectural differences between Uniswap V2 and Uniswap V3.

---

# The Two Equations We Already Know

Nothing new is introduced here.

We already know the Constant Product Equation:

```text
X × Y = L²
```

Notice that earlier we often wrote:

```text
K = X × Y
```

In Uniswap V3,

the lesson writes:

```text
L² = X × Y
```

So:

```text
K = L²
```

It's the same relationship,

just written using Liquidity (`L`) instead of `K`.

---

We also know the Spot Price equation:

```text
P = Y / X
```

This means:

> **Price of Token X in terms of Token Y**

For example:

```text
Token X = WETH

Token Y = USDT
```

Then:

```text
P = USDT / WETH
```

If:

```text
1 WETH = 3000 USDT
```

Then:

```text
P = 3000
```

---

# Important Discussion — Why Can't We Write `P = X / Y`?

A question came up while studying this derivation.

Can we simply write:

```text
P = X / Y
```

instead?

The answer is:

> **No.**

The reason is that **Price (`P`) has already been defined** as:

```text
P = Y / X
```

Changing it to:

```text
P = X / Y
```

would completely change the meaning of every equation.

For example:

```text
1 WETH = 3000 USDT
```

Then:

```text
P = Y / X

= 3000
```

But:

```text
X / Y

=

1 / 3000

≈ 0.000333
```

This is not the same price.

It is simply the reciprocal.

If we wanted to represent:

```text
X / Y
```

we would write:

```text
1 / P
```

instead of redefining `P`.

Throughout Uniswap V3,

the convention is always:

```text
P = Y / X
```

---

# Goal 1 — Derive Token X

We want an equation that only contains:

- Liquidity (`L`)
- Price (`P`)

and returns:

```text
Token X
```

We start with:

```text
X × Y = L²
```

and

```text
P = Y / X
```

Notice that we don't want `Y` anymore.

So we need to eliminate it.

---

# Step 1 — Divide by the Price

The clever trick is to divide by:

```text
P
```

So we write:

```text
L² / P
```

Now substitute both equations.

Since:

```text
L² = X × Y
```

and

```text
P = Y / X
```

we obtain:

```text
L² / P

=

(X × Y)

/ (Y / X)
```

---

# Step 2 — Simplify

Remember:

Dividing by a fraction means multiplying by its reciprocal.

So:

```text
(X × Y)

/ (Y / X)
```

becomes:

```text
X × Y × X / Y
```

Cancel the `Y`.

We're left with:

```text
X²
```

Therefore:

```text
L² / P = X²
```

---

# Step 3 — Remove the Square

Take the square root of both sides.

```text
√(L² / P)

=

√X²
```

The right side becomes:

```text
X
```

For the left side:

```text
√(a/b)

=

√a / √b
```

Therefore:

```text
√L²

/

√P
```

becomes:

```text
L / √P
```

Final result:

```text
X = L / √P
```

---

# Child Analogy

Imagine you know:

- The total amount of water flowing through a pipe (Liquidity).
- The water pressure (Price).

Using those two values,

this formula tells you how much water is in Tank X.

```text
Tank X

=

Liquidity

/

√Pressure
```

---

# Goal 2 — Derive Token Y

Now we repeat the process,

but this time we want:

```text
Y
```

instead of:

```text
X
```

We begin again with:

```text
X × Y = L²
```

and

```text
P = Y / X
```

Instead of dividing,

we multiply by `P`.

---

# Step 1 — Multiply by the Price

Write:

```text
L² × P
```

Substitute:

```text
L² × P

=

X × Y × (Y / X)
```

---

# Step 2 — Simplify

Cancel the `X`.

```text
X × Y × Y
-----------
     X
```

becomes:

```text
Y²
```

Therefore:

```text
L²P = Y²
```

---

# Step 3 — Remove the Square

Take the square root.

```text
√(L²P)

=

√Y²
```

Simplify:

```text
√L² × √P

=

Y
```

Since:

```text
√L² = L
```

we obtain:

```text
Y = L√P
```

---

# Experiment — Why Doesn't Division Work for Y?

While studying this derivation, an interesting question came up.

Since we derived **X** by dividing,

can we derive **Y** exactly the same way?

Let's try.

Start with:

```text
L² / P
```

Substitute:

```text
XY / (Y/X)
```

Rewrite:

```text
XY × X/Y
```

Cancel the `Y`.

The result is:

```text
X²
```

So we get:

```text
L² / P = X²
```

We wanted `Y`,

but we got `X` again.

No matter how we continue,

division always eliminates the `Y` because:

```text
P = Y/X
```

Dividing by:

```text
Y/X
```

is the same as multiplying by:

```text
X/Y
```

which naturally cancels the `Y`.

To eliminate `X` instead,

we must multiply by:

```text
Y/X
```

This is exactly why the instructor multiplies when deriving the equation for `Y`.

The algebra itself forces this choice.

---

# Final Equations

Given:

```text
Liquidity = L

Price = P
```

Token X is:

```text
X = L / √P
```

Token Y is:

```text
Y = L√P
```

---

# Key Takeaways

- Uniswap V2 stores Token X and Token Y directly.
- Uniswap V3 does not.
- Instead, Uniswap V3 stores:
  - Liquidity (`L`)
  - Current Price (`P`)
- From these values, Token X and Token Y can always be calculated.
- The two fundamental equations are:
  ```text
  X × Y = L²
  ```
  and
  ```text
  P = Y / X
  ```
- `P` is **always** defined as:
  ```text
  P = Y / X
  ```
  If we want `X / Y`, we use:
  ```text
  1 / P
  ```
- Token X is derived by dividing by `P`:
  ```text
  X = L / √P
  ```
- Token Y is derived by multiplying by `P`:
  ```text
  Y = L√P
  ```
- Division naturally eliminates `Y`, while multiplication naturally eliminates `X`, which is why the two derivations use different operations.
- These two equations become the foundation for almost all of the remaining Uniswap V3 liquidity mathematics.
