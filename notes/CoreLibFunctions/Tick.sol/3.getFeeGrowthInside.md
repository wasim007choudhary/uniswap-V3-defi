# 🧠 Uniswap V3 — `Tick.getFeeGrowthInside()`

> **Goal:** Find the cumulative fee growth that belongs to an LP's price range.

---

## 📍 The LP Range

An LP chooses two ticks:

```text
A = tickLower
B = tickUpper
```

So the position is:

```text
        BELOW              INSIDE              ABOVE

──────────A══════════════════════════════════B──────────→
          ↑                                      ↑
        lower                                  upper
```

Think of:

- **A** = left/lower boundary
- **B** = right/upper boundary
- **C** = `tickCurrent`, where the price is right now

The LP's range is:

```text
A <= C < B
```

So:

```text
C = A       → inside
A < C < B   → inside
C = B       → outside
C < A       → below the range
C > B       → above the range
```

---

## 🧭 Below and Above Have Fixed Meanings

This is extremely important.

### Below A

**Below A always means the LEFT side of A.**

```text
                    A
                    │
BELOW               │
←───────────────────│
```

### Above B

**Above B always means the RIGHT side of B.**

```text
                    B
                    │
                    │               ABOVE
                    │──────────────────→
```

Therefore:

```text
BELOW A = everything to the LEFT of A

ABOVE B = everything to the RIGHT of B
```

These meanings **do not change when C moves**.

---

## 🧠 `C` Does NOT Change What Below and Above Mean

Suppose C is inside:

```text
        BELOW              INSIDE              ABOVE

──────────A══════════════════C══════════════════B────────→
          ↑                                      ↑
        lower                                  upper
```

The meanings are still:

```text
BELOW A = LEFT of A

ABOVE B = RIGHT of B
```

Now move C below the range:

```text
        C          A                         B
        ↓          ↓                         ↓
────────●──────────●═════════════════════════●────────→
                  lower                     upper
```

**Below A is still the LEFT side of A.**

It does not suddenly become:

```text
C → A
```

It means the whole region:

```text
←──────────────── A
       BELOW
```

Likewise, if C moves above the range:

```text
A                         B          C
↓                         ↓          ↓
●═════════════════════════●──────────●────────→
lower                   upper
```

**Above B is still the RIGHT side of B.**

```text
B ───────────────────────────────→
              ABOVE
```

---

## 🔥 The Important Distinction — `Outside` vs `Below` / `Above`

> **YES — this is the important distinction to lock in.**

When **C is inside the range**, the `outside` side can be understood from each boundary:

```text
        BELOW              INSIDE              ABOVE

──────────A══════════════════C══════════════════B────────→
          ↑                                      ↑
        lower                                  upper
```

If we select **A**, then from A:

```text
A
│
←──────────────
   BELOW
   OUTSIDE
```

So:

> **For A, below A is the outside side.**

And if we select **B**:

```text
                              B
                              │
                              ───────────────→
                                  ABOVE
                                  OUTSIDE
```

So:

> **For B, above B is the outside side.**

In this case:

```text
A → BELOW = OUTSIDE

B → ABOVE = OUTSIDE
```

---

## 🔥 When C Is Outside the Range

Now suppose:

```text
C          A                         B
↓          ↓                         ↓
●──────────●═════════════════════════●────────→
```

C is outside the range, on the **left**.

Now look at the lower boundary **A**.

The `outside` side from A is considered toward the **RIGHT**:

```text
C          A                         B
↓          ↓                         ↓
●──────────●═════════════════════════●────────→
           │
           └──────────────────────────────→
                    OUTSIDE
```

That right side includes:

```text
A → B
```

and also everything after B:

```text
A ─────────────── B ─────────────────────→
│                  │
└──── OUTSIDE ─────┴─────────────────────→
```

So the `outside` side here includes **B and everything to the right until the line ends**.

Because the `outside` value represents the other side, we do:

```text
GLOBAL - OUTSIDE = BELOW A
```

So we recover the actual **below-A** side.

---

## 🔥 C Is Above the Range

Now suppose:

```text
A                         B          C
↓                         ↓          ↓
●═════════════════════════●──────────●────────→
```

C is outside the range, on the **right**.

Now look at the upper boundary **B**.

The `outside` side from B is considered toward the **LEFT**:

```text
A                         B          C
↓                         ↓          ↓
●═════════════════════════●──────────●────────→
│                         │
←─────────────────────────┘
          OUTSIDE
```

That left side includes:

```text
A
```

the whole LP range:

```text
A → B
```

and everything below A:

```text
←────────────────── A ═══════════════════ B
        OUTSIDE
```

So:

```text
GLOBAL - OUTSIDE = ABOVE B
```

---

## 🎯 What `C` Actually Does

`C` is used to decide **how to interpret the stored `feeGrowthOutside` value**.

This is the important distinction:

> 🔵 **Below / Above = fixed spatial regions relative to A and B.**

> 🔴 **`feeGrowthOutside` = a stored checkpoint whose interpretation depends on where C currently is relative to that boundary.**

So Uniswap asks:

```text
Where is C compared with A?

Where is C compared with B?
```

Then it knows whether to use:

```text
OUTSIDE
```

or:

```text
GLOBAL - OUTSIDE
```

---

## 💰 What Is `feeGrowthGlobal`?

The pool stores cumulative fee growth globally:

```solidity
feeGrowthGlobal0X128
feeGrowthGlobal1X128
```

There is one value for each token:

```text
0 → Token0

1 → Token1
```

Think of `feeGrowthGlobal` as:

> "How much cumulative fee growth has happened across the whole pool?"

But the LP does not want the whole pool's fee growth.

The LP wants only:

```text
A ─────────────── INSIDE ─────────────── B
```

So Uniswap must remove:

```text
BELOW
```

and:

```text
ABOVE
```

---

## 📐 Formula — Fee Growth Inside

```text
feeGrowthInside
    =
feeGrowthGlobal
    - feeGrowthBelow
    - feeGrowthAbove
```

### 🧒 In simple English:

Take **all fee growth**.

Remove the fee growth **below A**.

Remove the fee growth **above B**.

Whatever remains is the fee growth **inside A → B**.

```text
ALL
 ↓
remove BELOW
 ↓
remove ABOVE
 ↓
what remains = INSIDE
```

---

## 📜 Function

```solidity
function getFeeGrowthInside(
    mapping(int24 => Tick.Info) storage self,
    int24 tickLower,
    int24 tickUpper,
    int24 tickCurrent,
    uint256 feeGrowthGlobal0X128,
    uint256 feeGrowthGlobal1X128
) internal view returns (
    uint256 feeGrowthInside0X128,
    uint256 feeGrowthInside1X128
)
```

The function receives:

```text
tickLower
tickUpper
tickCurrent
feeGrowthGlobal0X128
feeGrowthGlobal1X128
```

and returns:

```text
feeGrowthInside0X128
feeGrowthInside1X128
```

There are two tokens:

```text
0 → Token0

1 → Token1
```

So the calculation is done separately for Token0 and Token1.

---

## 📦 Loading the Lower Tick

```solidity
Info storage lower = self[tickLower];
```

`self` is:

```solidity
mapping(int24 => Tick.Info) storage
```

So:

```solidity
self[tickLower]
```

means:

> "Go to the `Tick.Info` stored at `tickLower`."

Then:

```solidity
lower
```

is a storage reference to that tick.

So we can access:

```solidity
lower.feeGrowthOutside0X128
```

and:

```solidity
lower.feeGrowthOutside1X128
```

instead of repeatedly writing:

```solidity
self[tickLower].feeGrowthOutside0X128
```

---

## 📦 Loading the Upper Tick

```solidity
Info storage upper = self[tickUpper];
```

Same idea.

Now we have:

```text
lower → information belonging to A

upper → information belonging to B
```

So:

```text
A = tickLower

B = tickUpper

C = tickCurrent
```

---

## 💰 Creating the Below Variables

```solidity
uint256 feeGrowthBelow0X128;
uint256 feeGrowthBelow1X128;
```

These variables will eventually contain the fee growth **below A**.

There are two because Uniswap tracks two tokens:

```text
feeGrowthBelow0X128 → Token0

feeGrowthBelow1X128 → Token1
```

---

# 🔽 Finding `feeGrowthBelow`

The function checks:

```solidity
if (tickCurrent >= tickLower)
```

Using our letters:

```text
if (C >= A)
```

This asks:

> **"Is C at A or to the RIGHT of A?"**

---

## 🟢 When `C >= A`

Example:

```text
A                    C
↓                    ↓
●════════════════════●──────────────────→
```

Or exactly at A:

```text
A/C
 ↓
●══════════════════════════════════════→
```

The code uses:

```solidity
feeGrowthBelow0X128 =
    lower.feeGrowthOutside0X128;

feeGrowthBelow1X128 =
    lower.feeGrowthOutside1X128;
```

So:

```text
C >= A
   ↓
use OUTSIDE directly
   ↓
feeGrowthBelow
```

The important point is:

> The stored `feeGrowthOutside` value is interpreted so that it gives us the required **below-A** fee growth in this case.

---

## 🔴 When `C < A`

Example:

```text
C          A                         B
↓          ↓                         ↓
●──────────●═════════════════════════●────────→
```

C is now below the LP range.

The code uses:

```solidity
feeGrowthBelow0X128 =
    feeGrowthGlobal0X128 -
    lower.feeGrowthOutside0X128;
```

And for Token1:

```solidity
feeGrowthBelow1X128 =
    feeGrowthGlobal1X128 -
    lower.feeGrowthOutside1X128;
```

### 📐 Formula — Below When `C < A`

```text
feeGrowthBelow
    =
feeGrowthGlobal
    -
feeGrowthOutside
```

Why?

Because in this situation, the stored `feeGrowthOutside` value represents the **other side of A**.

```text
C          A                         B
↓          ↓                         ↓
●──────────●═════════════════════════●────────→
           │
           └────── other side ────────────────→
```

The other side contains everything from A to the right.

That includes:

```text
A → B
```

and everything after B.

Therefore:

```text
GLOBAL - OTHER SIDE
       ↓
   BELOW A
```

---

## 🧒 Simple Number Example

Imagine:

```text
GLOBAL = 100

OUTSIDE = 30
```

Then:

```text
BELOW = 100 - 30
```

Therefore:

```text
BELOW = 70
```

Think:

```text
GLOBAL
┌────────────────────────────────┐
│              100               │
└────────────────────────────────┘
              minus

OUTSIDE
┌──────────────┐
│      30      │
└──────────────┘
              =
BELOW
┌──────────────────────┐
│          70          │
└──────────────────────┘
```

# ⚠️ `Below` Does NOT Mean C → A

This is extremely important.

Suppose:

```text
C       A                  B
│       │                  │
●───────●══════════════════●────→
```

You might think:

```text
C → A
```

is "below."

❌ **No.**

**Below A means the whole side to the LEFT of A.**

It is not just:

```text
C → A
```

It means:

```text
←────────────────── A
        BELOW
```

So even if C is somewhere below A, the meaning of **below A** is still the entire left side of A.

# 🔼 Finding `feeGrowthAbove`

The function then creates:

```solidity
uint256 feeGrowthAbove0X128;
uint256 feeGrowthAbove1X128;
```

These will contain the fee growth **above B**.

Remember:

```text
ABOVE B = everything to the RIGHT of B
```

## 🚦 The Upper-Tick Condition

The function checks:

```solidity
if (tickCurrent < tickUpper)
```

Using our letters:

```text
if (C < B)
```

This asks:

> **"Is C to the LEFT of B?"**

---

## 🟢 When `C < B`

Example:

```text
A              C              B
↓              ↓              ↓
●══════════════●══════════════●────────→
```

The code uses:

```solidity
feeGrowthAbove0X128 =
    upper.feeGrowthOutside0X128;

feeGrowthAbove1X128 =
    upper.feeGrowthOutside1X128;
```

So:

```text
C < B
 ↓
use OUTSIDE directly
 ↓
feeGrowthAbove
```

---

## 🔴 When `C >= B`

Example:

```text
A                         B          C
↓                         ↓          ↓
●═════════════════════════●──────────●────→
```

C is above the LP range.

The code uses:

```solidity
feeGrowthAbove0X128 =
    feeGrowthGlobal0X128 -
    upper.feeGrowthOutside0X128;
```

And similarly:

```solidity
feeGrowthAbove1X128 =
    feeGrowthGlobal1X128 -
    upper.feeGrowthOutside1X128;
```

### 📐 Formula — Above When `C >= B`

```text
feeGrowthAbove
    =
feeGrowthGlobal
    -
feeGrowthOutside
```

Here, the stored outside checkpoint represents the **other side of B**, so:

```text
GLOBAL - OTHER SIDE
       ↓
    ABOVE B
```

---

# 🚪 Why Is the Lower Check `>=` but Upper Check `<`?

The LP range follows:

```text
A <= C < B
```

Therefore:

```text
C = A
```

means the price is at the **lower boundary** and is considered inside.

But:

```text
C = B
```

means the price is at the **upper boundary** and is considered outside.

So:

```text
LOWER A → inclusive

UPPER B → exclusive
```

That is why the conditions are:

```solidity
C >= A
```

and:

```solidity
C < B
```

---

# 🧩 The Complete Decision Table

| Boundary | Current position | Condition | What Uniswap uses |
|---|---|---|---|
| A = lower | `C >= A` | true | `lower.feeGrowthOutside` |
| A = lower | `C < A` | false | `global - lower.feeGrowthOutside` |
| B = upper | `C < B` | true | `upper.feeGrowthOutside` |
| B = upper | `C >= B` | false | `global - upper.feeGrowthOutside` |

# 🏁 Final Calculation

Once Uniswap has found:

```text
feeGrowthBelow
```

and:

```text
feeGrowthAbove
```

it calculates the fee growth inside the LP range.

For Token0:

```solidity
feeGrowthInside0X128 =
    feeGrowthGlobal0X128
    - feeGrowthBelow0X128
    - feeGrowthAbove0X128;
```

For Token1:

```solidity
feeGrowthInside1X128 =
    feeGrowthGlobal1X128
    - feeGrowthBelow1X128
    - feeGrowthAbove1X128;
```

### 📐 Final Formula

```text
feeGrowthInside
    =
feeGrowthGlobal
    -
feeGrowthBelow
    -
feeGrowthAbove
```

Or visually:

```text
                 GLOBAL
                    │
          ┌─────────┴─────────┐
          ↓                   ↓
       BELOW                 ABOVE
          │                   │
          └─────────┬─────────┘
                    ↓
               remove both
                    ↓
                  INSIDE
```

### 🧒 In one sentence:

> **Take all the pool's fee growth, remove everything below A and above B, and what is left is the fee growth inside the LP's range.**
