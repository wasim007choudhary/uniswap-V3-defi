# 🧹 `Tick.clear()` — Clearing Tick Data

```solidity

function clear(mapping(int24 => Tick.Info) storage self, int24 tick) internal {
    delete self[tick];
}
```

---

## 🎯 What does `clear()` do?

`clear()` **completely resets the stored `Tick.Info` data for one tick**.

Think of the mapping as:

```text
tick → Tick.Info
```

For example:

```text
Tick 100
   │
   ▼
┌────────────────────────────┐
│ liquidityGross = 500       │
│ liquidityNet   = 200       │
│ feeGrowth0     = 1000      │
│ feeGrowth1     = 2000      │
│ tickCumulative = 300       │
│ seconds/liquidity = 400    │
│ secondsOutside = 50        │
│ initialized = true         │
└────────────────────────────┘
```

After:

```solidity
clear(self, 100);
```

the stored struct becomes:

```text
Tick 100
   │
   ▼
┌────────────────────────────┐
│ liquidityGross = 0         │
│ liquidityNet   = 0         │
│ feeGrowth0     = 0         │
│ feeGrowth1     = 0         │
│ tickCumulative = 0         │
│ seconds/liquidity = 0      │
│ secondsOutside = 0         │
│ initialized = false        │
└────────────────────────────┘
```

---

# 1. 🔍 Function Parameters

## `self`

```solidity
mapping(int24 => Tick.Info) storage self
```

This is the mapping containing the information for every tick.

Conceptually:

```text
self
 │
 ├── tick -100 → Tick.Info
 ├── tick    0 → Tick.Info
 ├── tick  100 → Tick.Info
 ├── tick  500 → Tick.Info
 └── ...
```

---

## `tick`

```solidity
int24 tick
```

This tells the function **which tick to clear**.

Example:

```solidity
clear(self, 500);
```

means:

> Clear the `Tick.Info` stored for tick `500`.

---

# 2. 🔥 The Main Line

```solidity
delete self[tick];
```

This is the entire operation.

Break it down:

```solidity
self[tick]
```

means:

> Access the `Tick.Info` stored at this tick.

Then:

```solidity
delete
```

means:

> Reset that storage value to its default values.

Therefore:

```solidity
delete self[tick];
```

means:

> **Reset the entire `Tick.Info` struct stored at `tick`.**

---

# 3. 🧱 What Happens to the `Tick.Info` Struct?

The struct contains:

```solidity
struct Info {
    uint128 liquidityGross;
    int128 liquidityNet;
    uint256 feeGrowthOutside0X128;
    uint256 feeGrowthOutside1X128;
    int56 tickCumulativeOutside;
    uint160 secondsPerLiquidityOutsideX128;
    uint32 secondsOutside;
    bool initialized;
}
```

When:

```solidity
delete self[tick];
```

is executed, every field goes back to its **Solidity default value**.

| Field | Default value |
|---|---:|
| `liquidityGross` | `0` |
| `liquidityNet` | `0` |
| `feeGrowthOutside0X128` | `0` |
| `feeGrowthOutside1X128` | `0` |
| `tickCumulativeOutside` | `0` |
| `secondsPerLiquidityOutsideX128` | `0` |
| `secondsOutside` | `0` |
| `initialized` | `false` |

Suppose tick `500` currently contains:

```text
Tick 500

liquidityGross = 1000
liquidityNet = -300
feeGrowthOutside0 = 5000
feeGrowthOutside1 = 7000
tickCumulativeOutside = 100
secondsPerLiquidityOutside = 200
secondsOutside = 50

```

Now:

```solidity
delete self[500];
```

Everything becomes:

```text
Tick 500

liquidityGross = 0
liquidityNet = 0
feeGrowthOutside0 = 0
feeGrowthOutside1 = 0
tickCumulativeOutside = 0
secondsPerLiquidityOutside = 0
secondsOutside = 0
initialized = false
```

# 5. ⚠️ Mapping Entry vs Stored Value

A Solidity mapping does not behave exactly like a normal array/list where you physically remove a key.

Instead:

```solidity
delete self[tick];
```

resets the **value stored at that mapping key**.

So conceptually:

```text
BEFORE

self[500]
   ↓
Tick.Info {
    lots of data
}
```

After:

```solidity
delete self[500];
```

we get:

```text
self[500]
   ↓
Tick.Info {
    all default values
}
```

For Uniswap's purposes, the tick is now treated as **uninitialized**.

---

# 6. 🔥 Why Does This Matter?

A tick may have been initialized because a liquidity position used it as a boundary.

For example:

```text
Position
100 ─────────────────── 500
 ↑                       ↑
lower                   upper
```

Tick `500` contains information because it is a boundary.

Later, if liquidity is removed and **no position needs that tick anymore**, its `liquidityGross` can become:

```text
liquidityGross = 0
```

At that point the old tick data is no longer needed.

So Uniswap can call:

```solidity
clear(self, 500);
```

which executes:

```solidity
delete self[500];
```

and resets the entire tick record.

---

# 7. 🧠 Relationship With `initialized`

We previously learned:

```solidity
bool initialized;
```

This tells us whether the tick is initialized.

Before clearing:

```text
initialized = true
```

After:

```solidity
delete self[tick];
```

we get:

```text
initialized = false
```

because the default value of:

```solidity
bool
```

is:

```text
false
```

So:

```text
Initialized tick
       ↓
     delete
       ↓
Uninitialized tick
```

---

# 8. 🔗 Relationship With `liquidityGross`

We previously learned:

```text
liquidityGross
```

represents the total liquidity associated with that tick as a position boundary.

If it reaches:

```text
liquidityGross = 0
```

there is no liquidity currently associated with that tick.

`clear()` then wipes the remaining stored accounting data.

So the conceptual flow is:

```text
Tick has liquidity
       ↓
liquidityGross > 0
       ↓
Tick is initialized
       ↓
Liquidity is removed
       ↓
liquidityGross becomes 0
       ↓
Tick no longer needed
       ↓
clear()
       ↓
delete self[tick]
       ↓
All tick data → default values
       ↓
initialized = false
```

> **`clear()` = "This tick is no longer needed → wipe its entire `Tick.Info` storage record."**

```solidity

```
