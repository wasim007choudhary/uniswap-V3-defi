### 🎯 First: What is this library?

Very simply:

```text
TickMath
   │
   ├── tick → sqrtPriceX96
   │
   └── sqrtPriceX96 → tick
```

So the entire library exists to perform these **two conversions**.

We already know the conceptual formula:

```math
P = 1.0001^{tick}
```

Therefore:

```math
\sqrt P = \sqrt{1.0001^{tick}}
```

and then Uniswap encodes it as:

```math
sqrtPriceX96 = \sqrt P \times 2^{96}
```

So `TickMath` is basically turning that mathematical relationship into **EVM-compatible integer arithmetic**.

### 📌 The important part of the NatSpec

```solidity
/// @notice Computes sqrt price for ticks of size 1.0001,
/// i.e. sqrt(1.0001^tick) as fixed point Q64.96 numbers.
```

This tells us exactly what `getSqrtRatioAtTick()` will eventually calculate:

```math
\boxed{sqrtPriceX96 = \sqrt{1.0001^{tick}} \times 2^{96}}
```

And:

```solidity
/// Supports prices between 2**-128 and 2**128
```

means the valid tick range is chosen so that the represented prices stay within approximately:

```text
2^-128  ←──────────── price range ────────────→  2^128
```

That's why the next constants are the **minimum and maximum valid ticks**.

## 📍 `MIN_TICK` and `MAX_TICK`

```solidity
int24 internal constant MIN_TICK = -887272;
int24 internal constant MAX_TICK = -MIN_TICK;
```

### `MIN_TICK = -887272`

This means:

> **`-887272` is the minimum tick that Uniswap V3's `TickMath` supports.**

So the overall tick range is:

```text
MIN_TICK                                      MAX_TICK
  -887272  -----------------------------------  +887272
     ↑                                             ↑
 minimum tick                                  maximum tick
```

Therefore:

- `-887272` → lowest supported tick
- `+887272` → highest supported tick

And because:

```solidity
int24 internal constant MAX_TICK = -MIN_TICK;
```

we get:

```text
MAX_TICK = -(-887272)
         = +887272
```

### ⚠️ Important distinction — TickMath range vs tick spacing

It is tempting to say:

> "These are the min and max of the V3 tick line that can be initialized with the correct spacing."

**Not exactly.**

The `MIN_TICK` and `MAX_TICK` here are the **absolute TickMath boundaries**.

Then **tick spacing** determines which ticks within that overall range are actually usable/initializable for a particular V3 pool.

For example, conceptually:

```text
TickMath overall range

-887272 ------------------------------------------------ +887272
     |                                                       |
     MIN                                                     MAX


Pool with tickSpacing = 10

-887270 ---- -887260 ---- -887250 ---- ... ---- 887250 ---- 887260 ---- 887270
     ↑                                                        ↑
 usable ticks                                               usable ticks
```

So:

```text
TickMath
   ↓
defines the absolute minimum/maximum tick

tickSpacing
   ↓
selects which ticks inside that range can actually be initialized
```

### 💡 Every tick corresponds to a price

And this is the important connection to the next constants:

**each tick corresponds to a price, and therefore to a `sqrtPriceX96`.**

The relationship is:

```text
tick
  ↓
P = 1.0001^tick
  ↓
√P
  ↓
sqrtPriceX96
```

So at the conceptual level:

```text
-887272                                      +887272
   │                                             │
   ↓                                             ↓
 very low price                              very high price
   │                                             │
   ↓                                             ↓
 very low √P                                  very high √P
   │                                             │
   ↓                                             ↓
MIN_SQRT_RATIO                              MAX_SQRT_RATIO
```

### 🧠 Clean mental model

> `MIN_TICK` and `MAX_TICK` define the **absolute tick boundaries supported by TickMath**. Tick spacing then determines which ticks inside that range are valid initialization points for a particular pool. And every supported tick maps to a corresponding square-root price (`sqrtPriceX96`).

That is exactly the bridge we need for the next constants:

```solidity
uint160 internal constant MIN_SQRT_RATIO = 4295128739;
uint160 internal constant MAX_SQRT_RATIO = 1461446703485210103287273052203988822378723970342;
```

Those are the **sqrt-price boundaries corresponding to the tick boundaries**.
