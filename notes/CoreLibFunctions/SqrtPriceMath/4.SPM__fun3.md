# 🧮 `getNextSqrtPriceFromInput()` Dissection

```solidity
function getNextSqrtPriceFromInput(
    uint160 sqrtPX96,
    uint128 liquidity,
    uint256 amountIn,
    bool zeroForOne
)
    internal
    pure
    returns (uint160 sqrtQX96)
{
    require(sqrtPX96 > 0);
    require(liquidity > 0);

    // round to make sure that we don't pass the target price
    return zeroForOne
        ? getNextSqrtPriceFromAmount0RoundingUp(sqrtPX96, liquidity, amountIn, true)
        : getNextSqrtPriceFromAmount1RoundingDown(sqrtPX96, liquidity, amountIn, true);
}
```

---

# 🎯 Purpose

This function calculates the **next sqrt price** when the swap is Exact Input — meaning we know how much input token is going into the pool.

And importantly, this function **does not itself contain the price formulas**.

It chooses **which token0/token1 price-movement function** should be used:

- `zeroForOne == true` → token0 → token1 → use `getNextSqrtPriceFromAmount0RoundingUp()`
- `zeroForOne == false` → token1 → token0 → use `getNextSqrtPriceFromAmount1RoundingDown()`

---

Let's take these one at a time.

---

## `function getNextSqrtPriceFromInput`

```solidity
function getNextSqrtPriceFromInput(
```

This tells us the function's job:

> Given an **input amount**, calculate the **next sqrt price**.

The important word here is **Input**.

We already studied the two lower-level functions:

```text
getNextSqrtPriceFromAmount0RoundingUp()
```

and

```text
getNextSqrtPriceFromAmount1RoundingDown()
```

Those functions know **how token0 or token1 changes the sqrt price**.

This function sits one level above them.

It says:

> "I have an input amount. Based on the swap direction, which lower-level function should I call?"

---

# `sqrtPX96`

```solidity
uint160 sqrtPX96,
```

This is the **current sqrt price**.

Remember:

```text
sqrtPX96 = √P × 2^96
```

It is the price **before this input amount is applied**.

For example, conceptually:

```text
Current sqrt price
       ↓
    100
```

The function will calculate:

```text
Current price
      ↓
input amount applied
      ↓
Next sqrt price
```

---

# `liquidity`

```solidity
uint128 liquidity,
```

This is the **active liquidity** available for this price movement.

Not:

```text
total token balance
```

Not:

```text
total liquidity ever deposited
```

It is the liquidity currently active in the price range being processed.

We already saw that liquidity determines how much the price moves for a given token amount.

For token1:

```text
Δ√P = amount / liquidity
```

For token0:

```text
√Pnew = L × √P / (L + amount × √P)
```

So this function passes the active liquidity into the appropriate calculation.

---

# `amountIn`

```solidity
uint256 amountIn,
```

This is the amount of **input token** being supplied.

For example:

```text
amountIn = 100
```

means:

> We have 100 units of the input token available for this calculation.

The function does **not** care whether that input token is token0 or token1 yet.

That is determined by:

```solidity
zeroForOne
```

---

# `zeroForOne`

```solidity
bool zeroForOne
```

This tells us the **swap direction**.

There are two possibilities:

```text
zeroForOne = true
```

means:

```text
token0 → token1
```

and:

```text
zeroForOne = false
```

means:

```text
token1 → token0
```

Therefore:

| `zeroForOne` | Swap direction | Input token | Output token | Price direction |
|---|---|---|---|---|
| `true` | token0 → token1 | token0 | token1 | sqrt price ↓ |
| `false` | token1 → token0 | token1 | token0 | sqrt price ↑ |

This boolean is what allows the function to choose between the **amount0** and **amount1** price formulas.

```text
sqrtPX96
```

# 🧠 Function Body

```solidity
{
```

Now we enter the actual logic.

There are only **three things** this function does:

```text
1. Check current sqrt price is valid
2. Check liquidity is valid
3. Choose the correct price calculation based on swap direction
```

That's it.

It is basically a **dispatcher/wrapper** around the two functions we just studied.

---

# 🛡️ First Check

```solidity
require(sqrtPX96 > 0);
```

This says:

> The current sqrt price must be greater than zero.

Why?

Because the function is calculating a price.

A zero sqrt price is invalid for these calculations.

For example, our lower-level amount0 function contains calculations involving:

```text
1 / sqrtPrice
```

So we cannot allow:

```text
sqrtPX96 = 0
```

because that would mean division by zero / invalid price mathematics.

Therefore:

```text
sqrtPX96 > 0
```

must be true.

If:

```text
sqrtPX96 = 0
```

the function immediately reverts.

---

# 🛡️ Second Check

```solidity
require(liquidity > 0);
```

This says:

> There must be some active liquidity.

Why?

Because the price movement depends on liquidity.

For token1:

```text
Δ√P = amount / liquidity
```

If:

```text
liquidity = 0
```

we would have:

```text
amount / 0
```

which is invalid.

More fundamentally, there is no usable liquidity through which the input can move the price.

So:

```text
liquidity > 0
```

is required.

---

# 🎯 The Important Comment

```solidity
// round to make sure that we don't pass the target price
```

This comment is **very important**.

The function is not just trying to calculate some random next price.

It uses the rounding behavior of the two lower-level functions to make sure the calculated price **does not overshoot the target**.

For:

```text
token0 → token1
```

the price moves downward.

So it uses:

```text
getNextSqrtPriceFromAmount0RoundingUp()
```

For:

```text
token1 → token0
```

the price moves upward.

So it uses:

```text
getNextSqrtPriceFromAmount1RoundingDown()
```

The rounding is deliberately chosen so the price movement stays on the correct side.

---

# 🔀 The Return Statement

Now we reach the core:

```solidity
return zeroForOne
    ? getNextSqrtPriceFromAmount0RoundingUp(
        sqrtPX96,
        liquidity,
        amountIn,
        true
    )
    : getNextSqrtPriceFromAmount1RoundingDown(
        sqrtPX96,
        liquidity,
        amountIn,
        true
    );
```

This is a **ternary operator**.

It means:

```text
if zeroForOne is true
    use first function

otherwise
    use second function
```

Equivalent longer form:

```solidity
if (zeroForOne) {
    return getNextSqrtPriceFromAmount0RoundingUp(
        sqrtPX96,
        liquidity,
        amountIn,
        true
    );
} else {
    return getNextSqrtPriceFromAmount1RoundingDown(
        sqrtPX96,
        liquidity,
        amountIn,
        true
    );
}
```

---

# 🧠 Why Does `zeroForOne` Choose Amount0 vs Amount1?

This is the key connection.

## `zeroForOne == true`

```text
token0 → token1
```

Therefore:

```text
token0 is the input
```

So we need the function that calculates how **token0 input** changes the price:

```solidity
getNextSqrtPriceFromAmount0RoundingUp(...)
```

And because token0 is being **added to the pool**, the final argument is:

```solidity
true
```

So:

```solidity
getNextSqrtPriceFromAmount0RoundingUp(
    sqrtPX96,
    liquidity,
    amountIn,
    true
)
```

means:

> "Starting from this sqrt price, add this amount of token0 to the virtual reserves and calculate the new sqrt price."

The price moves:

```text
DOWN ↓
```

---

# `zeroForOne == false`

Now:

```text
token1 → token0
```

Therefore:

```text
token1 is the input
```

So we use:

```solidity
getNextSqrtPriceFromAmount1RoundingDown(...)
```

And again the final argument is:

```solidity
true
```

because token1 is being **added to the pool**.

So:

```solidity
getNextSqrtPriceFromAmount1RoundingDown(
    sqrtPX96,
    liquidity,
    amountIn,
    true
)
```

means:

> "Starting from this sqrt price, add this amount of token1 and calculate the new sqrt price."

The price moves:

```text
UP ↑
```

---

# 🔥 Why Is `add` Always `true` Here?

This is an important connection to the functions we just studied.

We are now inside:

```text
getNextSqrtPriceFromInput()
```

That means:

> We know the input amount.

During a swap, the trader's input token is **added to the pool's virtual reserves**.

Therefore:

```text
input token → pool
```

means:

```text
add = true
```

So both branches pass:

```text
true
```

as the final argument.

### If token0 is input:

```solidity
getNextSqrtPriceFromAmount0RoundingUp(..., true)
```

### If token1 is input:

```solidity
getNextSqrtPriceFromAmount1RoundingDown(..., true)
```

The `false` versions are not used here because those correspond to **removing** that token from the virtual reserves, which is what the separate `getNextSqrtPriceFromOutput()` function handles.

# 🧩 This Function Is Basically a Bridge

We can visualize the architecture:

```text
                 getNextSqrtPriceFromInput()
                            │
                    What is the direction?
                            │
                 ┌──────────┴──────────┐
                 │                     │
        zeroForOne = true      zeroForOne = false
                 │                     │
          token0 → token1          token1 → token0
                 │                     │
                 ▼                     ▼
   getNextSqrtPriceFrom       getNextSqrtPriceFrom
   Amount0RoundingUp()        Amount1RoundingDown()
                 │                     │
                 ▼                     ▼
          sqrt price ↓          sqrt price ↑
```

So this function itself contains almost **no mathematical formula**.

It is choosing the correct formula that we already studied.

If:


The most important thing to remember:

> **`getNextSqrtPriceFromInput()` does not invent a new price formula. It validates the inputs and dispatches the input amount to the correct token-specific sqrt-price function.**

And the connection to the two functions we just finished is:

```text
getNextSqrtPriceFromInput()
        ↓
"Which token is coming in?"
        ↓
token0 → getNextSqrtPriceFromAmount0RoundingUp(..., true)
token1 → getNextSqrtPriceFromAmount1RoundingDown(..., true)
```

The key idea:

> **Exact Input means the input token is added to the pool, so `add = true` in both branches. `zeroForOne` decides whether that input token is token0 or token1, and therefore which price formula is used.**
