# 9. Making the Division Exact

After passing all the safety checks, OpenZeppelin executes the following assembly:

```solidity
uint256 remainder;

assembly ("memory-safe") {
    remainder := mulmod(x, y, denominator)

    upperPart := sub(upperPart, gt(remainder, lowerPart))
    lowerPart := sub(lowerPart, remainder)
}
```

This is one of the most important parts of the entire algorithm.

At first glance, it looks strange.

Why would we intentionally modify the product we just spent so much effort computing?

The answer is:

> **Because the modular inverse can only divide an exact multiple of the denominator.**

So before we can use the modular inverse,

we must first eliminate the remainder.

---

# Step 1 — Compute the Remainder

The first line is

```solidity
remainder := mulmod(x, y, denominator)
```

Remember what `mulmod()` does.

It computes

```text
(x × y) % denominator
```

without overflowing.

So after this instruction,

we know exactly what would be left over if we divided the product by the denominator.

---

# Example

Suppose

```text
Product = 43

Denominator = 5
```

Then

```text
43 ÷ 5

=

8 remainder 3
```

So

```text
remainder = 3
```

Nothing surprising so far.

---

# Step 2 — Why Compute the Remainder?

The product can always be written as

```text
Product

=

Quotient × Denominator

+

Remainder
```

This identity is always true.

Example:

```text
43

=

8 × 5

+

3
```

---

# Step 3 — Remove the Remainder

Now subtract the remainder from both sides.

```text
43 - 3

=

(8 × 5 + 3)

-

3
```

Simplify.

```text
40

=

8 × 5
```

Notice something incredible.

The remainder disappeared.

Now the numerator is a perfect multiple of the denominator.

There is nothing left over.

---

# Did We Change the Product?

Yes.

The original product was

```text
43
```

The new value is

```text
40
```

So yes,

the product changed.

This often worries people.

---

# Did We Change the Quotient?

No.

Originally,

```text
43 ÷ 5

=

8 remainder 3
```

After subtraction,

```text
40 ÷ 5

=

8 remainder 0
```

The quotient stayed exactly the same.

Only the leftover disappeared.

---

# Child Analogy

Suppose you have

```text
43 chocolates.
```

You want to pack them into boxes of

```text
5.
```

You obtain

```text
8 full boxes

+

3 loose chocolates.
```

Now throw away the loose chocolates.

You now have

```text
40 chocolates.
```

How many full boxes do you still have?

```text
8.
```

The number of full boxes never changed.

Only the loose chocolates disappeared.

That is exactly what this subtraction does.

---

# Does This Lose Money?

This is one of the most common questions.

At first it looks like we are destroying value.

After all,

```text
43

↓

40
```

looks like a loss.

However,

remember what `mulDiv()` promises to return.

It does **not** return the product.

It returns

```text
floor(Product ÷ Denominator)
```

For our example,

```text
floor(43 ÷ 5)

=

8
```

and

```text
40 ÷ 5

=

8
```

The returned integer is exactly the same.

Nothing extra is lost.

---

# Then What Happened to the Remainder?

Mathematically,

the remainder represents value.

However,

on-chain,

that value is smaller than the smallest transferable unit.

Example:

Suppose the exact answer is

```text
333.333333... wei
```

Can Ethereum transfer

```text
0.333333... wei
```

No.

The smallest transferable unit is already

```text
1 wei.
```

So the protocol can only send

```text
333 wei.
```

The fractional part was never transferable.

`mulDiv()` does not steal it.

It simply removes it before using the modular inverse,

because integer arithmetic would discard it anyway.

---

# Why Must We Remove It?

Suppose we tried to compute

```text
43 ÷ 5
```

using the modular inverse.

The modular inverse only works correctly for

```text
ExactNumerator

=

Quotient × Denominator
```

It cannot directly divide

```text
Quotient × Denominator

+

Remainder.
```

Therefore we first transform

```text
Product

↓

Exact Product
```

by subtracting the remainder.

Only then is the modular inverse mathematically valid.

---

# The Beautiful Identity

Everything comes from one equation.

```text
Product

=

Quotient × Denominator

+

Remainder
```

Subtract the remainder.

```text
Product

-

Remainder

=

Quotient × Denominator
```

Now the division is exact.

That is the entire purpose of this section.

---

# Key Takeaways

* `mulmod()` computes the exact remainder without overflowing.

* Every integer division satisfies

  ```
  Product = Quotient × Denominator + Remainder
  ```

* Subtracting the remainder produces

  ```
  Product - Remainder = Quotient × Denominator
  ```

* The quotient does not change.

* Only the remainder disappears.

* The modular inverse requires this exact divisibility before it can replace division with multiplication.
